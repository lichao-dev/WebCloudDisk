# 如何阅读当前微服务代码

建议不要按目录从上到下看。先理解三个服务进程，再沿一次 HTTP 请求纵向追踪到 RPC、业务层和数据库。

## 第一遍：了解进程和协议

先看这三个入口：

1. [`src/gateway/main.cc`](../src/gateway/main.cc)：HTTP API 网关。
2. [`src/user_service/main.cc`](../src/user_service/main.cc)：用户 RPC 服务。
3. [`src/file_service/main.cc`](../src/file_service/main.cc)：文件 RPC 服务。

共同启动流程是：

```text
解析 --config
  ↓
Config::load()
  ↓
Log::init()
  ↓
组装当前进程的依赖
  ↓
监听 HTTP 或 RPC 端口
  ↓
等待 SIGINT / SIGTERM 后停止
```

然后看协议目录：

- [`proto/common.proto`](../proto/common.proto)：共享状态、用户和文件消息，不对应独立服务。
- [`proto/user_service.proto`](../proto/user_service.proto)：注册、登录和当前用户 RPC。
- [`proto/file_service.proto`](../proto/file_service.proto)：文件列表、上传和下载 RPC。

## 第二遍：理解网关

阅读 [`GatewayApplication.cc`](../src/gateway/GatewayApplication.cc)，重点看：

- `register_routes()` 如何保留原 REST API。
- JSON 和 multipart 请求怎样转换成 Protobuf 消息。
- sRPC 传输错误为什么映射为 HTTP 502。
- RPC 返回的业务状态怎样映射为原 HTTP 状态码。
- `AuthMiddleware` 如何在网关校验 Bearer JWT。

网关只处理 HTTP 边界和 RPC 转发，不直接访问 MySQL、文件系统或 RabbitMQ。

## 第三遍：沿注册接口阅读

注册链路最适合入门：

```text
POST /api/v1/auth/register
  ↓
GatewayApplication::register_user()
  ↓
UserRpcServiceImpl::Register()
  ↓
AuthService::register_user()
  ├─ PasswordHasher::hash()
  └─ UserRepository::create()
       ↓
     MySqlClient::create_task()
```

依次看：

1. [`GatewayApplication.cc`](../src/gateway/GatewayApplication.cc)
2. [`UserRpcServiceImpl.cc`](../src/rpc/UserRpcServiceImpl.cc)
3. [`AuthService.cc`](../src/service/AuthService.cc)
4. [`PasswordHasher.cc`](../src/security/PasswordHasher.cc)
5. [`UserRepository.cc`](../src/repository/UserRepository.cc)
6. [`MySqlClient.cc`](../src/database/MySqlClient.cc)

## 第四遍：看登录和鉴权

登录流程：

```text
GatewayApplication::login()
  ↓
UserRpcServiceImpl::Login()
  ↓
AuthService::login()
  ├─ UserRepository::find_by_username()
  ├─ PasswordHasher::verify()
  └─ JwtService::generate()
```

受保护接口则先在网关执行：

```text
AuthMiddleware::authenticate()
  ↓
JwtService::verify()
  ↓
把 user_id 写入 RPC 请求
```

这里重点理解：密码只在用户服务中处理；JWT 在用户服务签发，在网关验证。

## 第五遍：看文件业务

文件列表：

```text
GatewayApplication::list_files()
  ↓
FileRpcServiceImpl::ListFiles()
  ↓
FileService::list()
  ↓
FileRepository::list_by_user()
```

文件上传：

```text
GatewayApplication::upload_file()
  ↓ Protobuf bytes
FileRpcServiceImpl::UploadFile()
  ↓
FileService::upload()
  ├─ Sha256::hex()
  ├─ FileStorage::store_if_absent()
  ├─ FileRepository::create()
  └─ RabbitMqBackupTaskPublisher::publish()（可选）
```

文件下载按反方向通过 Protobuf `bytes` 返回网关。当前设计适合同机开发，上传和下载会多一次序列化与内存复制。

## 第六遍：理解异步任务

业务层通过 [`TaskScheduler.h`](../src/common/TaskScheduler.h) 描述两种操作：

- `add_task()`：把 MySQL 或 RPC 任务追加到当前 Workflow 序列。
- `add_compute_task()`：把 PBKDF2、文件哈希、同步写盘等工作放入计算队列。

HTTP 网关使用 `HttpResp::add_task()` 追加 RPC 客户端任务；RPC 服务使用
`RPCContext::get_series()->push_back()` 追加数据库和计算任务。这样 Service 无需依赖具体的 HTTP 或 RPC 上下文。
